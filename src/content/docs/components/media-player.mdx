## Usage

Put a native `<video>` or `<audio>` and one layout inside the player. The player owns a single media store; every control reads state from it and changes playback through its request pipeline, so buttons, keys and gestures always agree.

### Audio

An `<audio>` element works the same way. Give it an in-flow `tp-media-controls` with `visibility="always"` so the bar stays visible in the page's color scheme, and pick the controls a podcast or voice note needs.

### Choosing controls

`hide` removes built-in controls from a layout by name, and `seek-buttons` adds skip back and forward next to play. Seek distance comes from the player's `seek-step`.

Hidden controls are gone, not disabled. Controls the media cannot support, such as picture-in-picture in some browsers, hide themselves.

### Layout regions and speeds

The video layout's `top`, `center`, `bottom-start` and `bottom-end` slots replace that region's default content, here the title in `top`. `playback-rates` sets the options of the speed menu as a space-separated list.

### Keyboard

With focus anywhere in the player, Space or K plays and pauses, the arrow keys seek and change volume, M mutes, F toggles fullscreen and C toggles captions. Shortcuts are published through `aria-keyshortcuts` and appear in the layout's tooltips. Set `hotkey-scope="document"` to route keys from anywhere on the page to the most recently used player.
