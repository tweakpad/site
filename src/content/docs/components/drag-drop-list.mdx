## Usage

Items are plain data, so the list is fed from script: set `defaultValue` (uncontrolled) or `value` (controlled) before the first render, with each item's `id` and `label`. Each drag hovers a preview order; a drop commits a new array, and Escape or a drop outside restores the committed order.

### Keyboard

Every row has a named handle Button. Focus it, press Space or Enter to pick the item up, move it with the arrow keys, and press Space or Enter again to drop it; Escape cancels. A live region announces each step.

### Reading the value

`tp-value-change` fires with each proposed order and can be cancelled; `tp-value-commit` fires once the drop has settled. Read `value` then to save the order.

### Activation and swapping

By default only the handle starts a pointer drag, which keeps text in the row selectable. `activation="item"` lets the whole row start one, after a short delay or movement so clicks still work. `reorder-mode="swap"` exchanges two items instead of shifting the ones between them.

`orientation="horizontal"` lays the items out in a row and moves them with the left and right arrow keys, mirrored for right-to-left text.

### Disabled and read-only

`disabled` and `readonly` stop reordering and cancel a drag in progress, while leaving the rows readable. Use `readonly` when the order is visible but locked, such as while a save is pending.

### Connected lists

Lists that share one `DragDropManager` from `@tweakpad/ui/drag-drop`, each with a unique `group`, can pass items between them, such as columns on a board. `moveItem()` performs the same atomic move from code, for example from a "Move to Ready" menu action.
