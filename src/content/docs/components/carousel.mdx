## Usage

Each child of `tp-carousel` is one slide. Previous and next Buttons, arrow keys, swipe and the indicators all move the same numeric selection, and the current position is announced politely. Always give the Carousel a `label`, and size it through CSS: it fills the inline size it is given.

### Several per view

Layout, navigation and indicator settings live in the `options` property. `layout.itemsPerView` accepts fractions, so a partly visible next slide hints that there is more; `items-per-movement` sets how far each step moves.

### Indicators and placement

`indicators.type` is `fraction` by default, or `bullets` and `progress`. Set `clickable: true` to make bullets real Buttons. `navigation.placement` puts the arrows in the `footer`, `inside` the viewport or `outside` it.

### Loop and autoplay

`loop` lets navigation wrap past either end. `autoplay` sets an interval in milliseconds and adds a Pause/Resume Button before the slides; hover, focus, reduced motion and hidden tabs pause the timer automatically.

Use autoplay sparingly: moving content is hard to read and easy to miss. Prefer it for decorative or repeated content, never for the only path to information.

### Vertical

`orientation="vertical"` moves the track, keys and swipe to the block axis. A vertical Carousel needs a definite block size.

### Events

`tp-value-change` proposes a new position and can be canceled; `tp-value-commit` follows once it is accepted. Read the committed position from `index`, or drive the Carousel through its `controller`.

  align="stretch"

    <div style="display:grid;place-content:center;min-block-size:8rem;border-radius:var(--tp-radius-lg);background:var(--tp-muted)">Import your data</div>

});`}

### Keyboard

Arrow keys follow the active axis and writing direction; Home and End jump to the first and last slide. Keys owned by a control inside a slide, such as a text field or slider, stay with that control.
