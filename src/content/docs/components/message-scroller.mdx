## Usage

The scroller owns only scrolling: it opens at the latest message, follows growth while the reader is at the end, and keeps their place when they scroll away. Your application owns the messages and transport; Message and Bubble supply the rows.

Explicit composition is one Viewport containing one Content of Items, plus an optional Return control. Scroll up in the example above and the Return control appears to bring the reader back to the end.

### Streaming replies

While the reader is pinned to the end, `follow` keeps the viewport on the growing reply. A turn marked `scroll-anchor` holds its prompt at the reading line, so the question stays in view while the answer fills in below it. Update streamed text in place and keep the Item's `message-id`.

  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-3);max-inline-size:28rem;margin-inline:auto;inline-size:100%">
  <tp-message-scroller id="message-scroller-stream" label="Assistant conversation" style="border:var(--tp-border-width) solid var(--tp-border);border-radius:var(--tp-radius-xl);--tp-message-scroller-height:18rem">

      <tp-message aria-label="Assistant">
        <tp-bubble variant="ghost">Hi Dana, ask me anything about your workspace.</tp-bubble>
      </tp-message>
    </tp-message-scroller-item>
  </tp-message-scroller>
  <tp-button id="message-scroller-ask" variant="outline">Ask a question</tp-button>
</div>`}
  script={`const scroller = document.getElementById('message-scroller-stream');
const ask = document.getElementById('message-scroller-ask');
const turns = [
  ['How many seats are free?', 'You have 2 of 20 seats free. Two guests have not signed in for 90 days; removing them would free two more without changing your plan.'],
  ['Who can approve invoices?', 'Owners and members with the Billing admin role. Right now that is you and Marcus Chen. Add the role from Members → Roles.'],
  ['When does the plan renew?', 'Your Team plan renews on November 1. The estimated total is $480 for 20 seats, billed to the card ending in 4242.'],
];
let count = 0;

const row = (id, align, text, anchor) => {
  const item = document.createElement('tp-message-scroller-item');
  item.messageId = id;
  item.scrollAnchor = anchor;
  const message = document.createElement('tp-message');
  message.align = align;
  message.setAttribute('aria-label', align === 'end' ? 'You' : 'Assistant');
  const bubble = document.createElement('tp-bubble');
  bubble.align = align;
  bubble.variant = align === 'end' ? 'default' : 'ghost';
  bubble.textContent = text;
  message.append(bubble);
  item.append(message);
  scroller.append(item);
  return bubble;
};

ask.addEventListener('click', () => {
  const [question, answer] = turns[count % turns.length];
  count += 1;
  ask.disabled = true;
  row('prompt-' + count, 'end', question, true);
  const reply = row('reply-' + count, 'start', '', false);
  const words = answer.split(' ');
  let index = 0;
  const timer = setInterval(() => {
    index += 1;
    reply.textContent = words.slice(0, index).join(' ');
    if (index >= words.length) {
      clearInterval(timer);
      ask.disabled = false;
    }
  }, 60);
});`}
/>

This example uses the shorthand: Items placed directly in the Root get a generated Viewport, Content and Return control.

### Jump to a message

`scrollToMessage`, `scrollToStart` and `scrollToEnd` return a receipt whose `finished` promise settles as `completed`, `superseded` or `rejected`. Use them for an outline, search results or a "jump to unread" control.

Commands preserve focus, so the reader stays on the button they pressed. A message command releases following; a completed end command resumes it.

### Opening position

`initial-position` places the reader once, on the first content: `end` (default) for chats, `start` for a log read from the top, or `last-anchor` to open at the latest long turn. Changing it later never moves the reader.
